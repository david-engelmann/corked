# stickler Contract

This Contract is the executable spec for stickler. Every obligation is checked by a named test or by a named check. The Contract is reported as met or not met in the README programme status.

## Setup obligations

- SETUP-1. The repo carries AGENTS.md with the canonical template verbatim
  above its marked line and the repo annex below it. Test,
  tests/test_setup.py.
- SETUP-2. The README programme status states the closed round count out
  of 100 and reports this Contract as met or not met. Test,
  tests/test_setup.py.
- SETUP-3. The codepoint scan at scripts/codepoint_scan.py counts U+2014
  and U+2013 in every Markdown and text file in the repo and requires
  zero of each. The scan runs in the local gate and in CI.
- SETUP-4. Every fixture and example committed to this repo is synthetic
  and written for this repo. Nothing real is ever committed. Check, a
  manual sanitization review of every added fixture and example, with
  its result recorded in the gate report.

## First slice obligations, stub form

The full Contract for the first slice is the first build act of this repo. These stubs state the obligations the first slice will be held to, in the form they will be extended.

- CK-1. A review takes one diff and returns a verdict of accepted or sent back. A sent back verdict carries at least one objection and an accepted verdict carries none. Test, the first slice tests.
- CK-2. Every objection names the flaw, the standard it violates, and the rewrite that would be accepted, and an objection missing any of the three is not a valid objection. Test, the first slice tests.
- CK-3. Objections speak to naming, structure, and smell, and each objection states which of the three it is. Test, the first slice tests.
- CK-4. The review runs against recorded model output or local rules and never needs a paid API call. Test, the first slice tests.

## First slice obligations, full form

This section extends the stub obligations above. The stub text stands as the record of what was promised at setup, and this section states the same four obligations in the form the first slice is held to. Where the two readings disagree, this section governs.

- CK-1. A review is a JSON object holding diff_label and objections. The diff_label is a non empty string and objections is a list. The validate function in src/stickler/review.py returns the list of defects it finds and never raises, whatever it is handed. A value that is not an object, a missing field, a field of the wrong type, and a blank string are each named as defects in that list. The verdict is accepted when the defect list is empty and the objections list is empty. The verdict is sent back when the defect list is empty and the objections list holds at least one objection. The verdict is invalid when the defect list is not empty, and an invalid review is never accepted and never sent back. Test, tests/test_review.py.
- CK-2. Every objection is an object holding flaw, standard, rewrite, and category. The flaw, the standard, and the rewrite are non empty strings. The category is one of naming, structure, and smell. An objection missing a field, holding a blank field, or holding a category outside the three is named in the defect list with its position in the objections list, and a review holding such an objection is invalid. The built in checker emits only complete objections, so a review built by the checker is never invalid for incompleteness. Test, tests/test_review.py and tests/test_checker.py.
- CK-3. Objections speak to naming, structure, and smell, and the built in checker in src/stickler/checker.py raises four shapes and no others. The checker reads a unified diff as text and reads only added lines. An added line begins with a plus sign, and the three plus header line is not an added line. Removed lines and context lines are never read. Each shape raises at most one objection on one line, and objections come back in line order and, on one line, in the order the shapes are stated here. The first shape is a bare except clause on an added line, and it raises a smell objection whose rewrite is the same line with the bare clause replaced by a handler naming Exception. The second shape is a print call on an added line, and it raises a smell objection whose rewrite is the same line with the print call replaced by a logger.debug call. A print name that belongs to a longer name or to an attribute does not raise. The third shape is a mutable default on an added def line, and it raises a structure objection whose rewrite is the same def line with the default replaced by None. The mutable defaults seen are an empty list, an empty dict, and an empty set call, and they are seen on the def line itself. The fourth shape is a placeholder name, read as the target of an assignment or as the name of a function on a def line, and a placeholder is exactly one of data2, temp2, foo, bar, stuff, and thing. A placeholder raises a naming objection. The rewrite for a placeholder assignment draws its name from the assigned value when the right hand side is a simple call on a plain name or a literal. For a simple call the drawn name is the callee name with its leading word dropped when the callee name holds more than one word, and the callee name itself when it holds one word. For a literal the drawn name is text for a string, items for a list, mapping for a dict, and number for a number. When the drawn name would itself be a placeholder or a Python keyword, and in every other case, and for a placeholder function name, the rewrite invents no name and instead instructs the rename, stating that the name must say what the value holds or what the function does. The limits are part of the obligation. The checker reads text and not syntax, so a matching shape inside a string literal on an added line raises like code, a statement split across lines is read one line at a time, and shapes the four do not name never raise. Test, tests/test_checker.py.
- CK-4. The review runs against recorded model output or local rules and never needs a paid API call. The command line in src/stickler/cli.py carries two commands. The check command reads a unified diff file, builds a review from the checker output under the file name as its label, and prints the rendering. The render command reads a recorded review as JSON and prints the rendering. The rendering in src/stickler/render.py is one deterministic form shared by both commands, so the same review always renders byte identical output. The exit code is 0 for an accepted review, 1 for a sent back review, and 2 for invalid input, with the defects printed in the rendering. Input that cannot be read, and a render file that does not hold a JSON review, are invalid input. A recorded review committed under examples is held byte identical against its stored rendering by a golden test. Test, tests/test_cli.py and tests/test_render.py.

## Round 2 obligations, full form

This section states the obligations of the second slice in full form. It extends CK-3 and CK-4, and the earlier text is left standing as the record of the first slice. Where the two readings disagree, this section governs.

- CK-5. This obligation extends CK-3 and completes the definition time family, the shapes that read values computed once when a definition is read and then shared by every call or every instance. The checker raises six shapes and no others, the four stated in CK-3 and the two stated here, and where CK-3 speaks of four shapes this obligation governs. Each new shape raises at most one objection on one line, and on one line the objections come back in the order the shapes are stated across CK-3 and this obligation, so the call default shape stands fifth and the class attribute shape stands sixth. The fifth shape is a call default on an added def line. A call default is a parameter default whose text is a call, read as a plain or dotted name followed by a parenthesised argument list that closes at the end of the default text, and a default the mutable default shape sees is not a call default. The call runs once when the definition is read, so every call that omits the argument shares the one result it produced. The shape raises a structure objection whose rewrite is the same def line with every call default on the line replaced by None, with the instruction appended that each replaced default is built inside the body under a None check. The sixth shape is a class attribute on an added line, and its class context is read from the diff itself. The checker walks the lines of the diff in order and keeps a stack of open blocks, and only context lines and added lines are read, with removed lines never read. A hunk header empties the stack, and a diff file header empties the stack. The indentation of a read line is the count of its leading space characters. Before a read line is judged, every open block whose indentation is the same as the line or deeper is closed. A class opener is a read line whose stripped text begins with the word class and whose text ends with a colon. A function opener is a read line that matches the def line shape. An opener is pushed onto the stack after its own line is judged, and no other line opens a block. A line sits directly in a class body when the innermost open block left on the stack is a class opener. The shape fires when a line sitting directly in a class body holds a plain or annotated assignment of a name to one literal, where the right hand side is a list literal, a dict literal, or a set literal that opens at its first character and closes at its last. The shape raises a structure objection whose rewrite instructs the move into the initializer, naming the attribute through self with the literal as written and the class level assignment removed. The limits are part of the obligation. A literal assignment at module level sits in no class body and draws nothing. A literal assignment inside a function inside a class sits in the function and draws nothing. A literal assignment inside a class inside a function sits in the class and draws the shape. A block the checker does not track, such as a conditional inside a class body, opens nothing, so a literal assignment under it still reads as sitting in the class body. A hunk that begins inside a class body without showing the class line carries no class context, because the stack starts empty at the hunk header. Test, tests/test_checker.py.
- CK-6. A change set is a JSON object holding files, and files is a list of entries. Each entry is an object holding file and diff. The file field is a non empty string naming the file, and the diff field is a string holding a unified diff in the shape the checker reads, and the diff may be empty. File names need not be unique, and entries are judged in the order given. The load function in src/stickler/changeset.py returns the list of defects it finds and never raises, whatever it is handed. A value that is not an object, a missing field, a field of the wrong type, and a blank file name are each named as defects in that list, with the position of the entry in the files list. The set check runs the checker over the diff of every entry and renders one review in src/stickler/render.py. The rendering names each file in the order given and gives either the clean word for a file whose diff raises nothing or the judgements for that file in line order, each judgement rendered with its category, its flaw, its standard, and its rewrite. The rendering ends with a summary that counts every judgement across the set, counts the judgements by shape for each shape that raised at least once in the order the shapes are stated across CK-3 and CK-5, and names the files with judgements worst first, with the most judgements first and ties broken by file name. The six shape names are bare except, print call, mutable default, placeholder name, call default, and class attribute. The set review is a pure function of the change set, and the same change set always renders byte identical output. The command line gains a third command beside check and render. The review command in src/stickler/cli.py reads a change set file and prints the set review. The exit code is 0 when no judgement stands and 1 when at least one judgement stands. The exit code is 2 when the change set file is malformed, and a file that cannot be read, a file that cannot be decoded as UTF-8 text, a file whose JSON nesting is too deep to read, and a file that does not hold a JSON change set are malformed, with the defects printed in the rendering. A change set committed under examples is held byte identical against its stored rendering by a golden test. Test, tests/test_changeset.py, tests/test_render.py, and tests/test_cli.py.

## Round 2 repair amendments

This section amends the obligations above. Each amendment names the obligation it amends and the review finding it closes, and the earlier text is left standing.

- FIX-CK-8. Amends CK-6 and CK-1 and closes red team finding F1 and standards finding S1. A JSON input can carry an unpaired surrogate in a text field where a file read as UTF-8 text cannot, and a string holding an unpaired surrogate cannot be printed as UTF-8 text. In the change set loader in src/stickler/changeset.py, an entry whose file name holds an unpaired surrogate draws a defect naming the file field with the position of the entry in the files list, and an entry whose diff holds an unpaired surrogate draws a defect naming the diff field the same way, so no loader valid change set carries a surrogate into a rendering and the review command names the defect and exits with code 2. The recorded review surface holds the same rule. In the review validator in src/stickler/review.py, a diff label holding an unpaired surrogate draws a defect naming the diff label, and an objection text field holding an unpaired surrogate draws a defect naming that field with the position of the objection in the objections list, and a review holding either is invalid. A diff label that cannot be printed is never printed, and the rendering of a review whose label holds an unpaired surrogate names the review with the unnamed review label the rendering already uses when a review holds no usable label. Test, tests/test_changeset.py, tests/test_review.py, tests/test_render.py, and tests/test_cli.py.
- FIX-CK-9. Amends CK-5 and closes red team finding F2. A read line whose content is empty or holds only spaces neither opens nor closes a block, and the walk passes over such a line before any other reading of it, for context lines and added lines alike. A blank line inside a class body therefore leaves the class open for the lines that follow it, and the written forms of a blank line read the same way, a line holding nothing after its marker, a line holding only spaces after its marker, and a truly empty line standing in the diff text. Test, tests/test_checker.py.
- FIX-CK-10. Amends CK-5 and CK-3 and closes red team finding F3. The quote scanning the checker shares reads a backslash inside a string as escaping the character that follows it, so an escaped quote does not close the string it stands in. The rule is whole across the checker and holds in the call reading, in the argument list walk of the call default rewrite, in the top level splitting, in the default span reading, and in the literal readings, and it holds for the Round 1 shapes that share the scanning as it holds for the Round 2 shapes. Test, tests/test_checker.py.
- FIX-CK-11. Amends CK-5 and closes red team finding F4. A diff file header empties the stack in either of its written forms. The git form is a line opening with the word diff, and the plain form is a line opening with three minus signs and a space and its pair line opening with three plus signs and a space, and each line of the plain form empties the stack wherever it stands in the text. Test, tests/test_checker.py.
- FIX-CK-12. Amends FIX-CK-9 and closes the ungraded observation of the Round 2 re-review. A blank line for the context rule is a line whose content is empty or holds only whitespace characters, spaces and tabs alike, and the spaces wording of FIX-CK-9 is read that way. A tab only line inside a class body therefore leaves the class open for the lines that follow it, as a spaces only line does. Test, tests/test_checker.py.
